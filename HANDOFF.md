# Передача проекта ВКР

## Что готово

В текущем сценарии врач записывает разговор на телефон и загружает готовый аудиофайл в приложение на Windows. GigaAM v3 CTC локально расшифровывает запись. Врач может проверить и поправить текст. Qwen 2.5 размечает вопросы и ответы, а приложение собирает редактируемый черновик предоперационного осмотра, показывает цитаты из расшифровки и список того, что нужно уточнить. Сеанс сохраняется в JSON, черновик экспортируется в Word, PDF или TXT.

В свежей копии запустите `setup.cmd`, затем `launch-protocol.cmd`. Для первой установки нужен интернет. Для демонстрации запишите на телефон [вымышленный диалог](data/references/dev01.txt). Загрузите файл в приложение, нажмите «Обработать аудио», проверьте текст и нажмите «Протокол осмотра…». Подробности установки и ссылки на исходники есть в [README](README.md).

Сейчас в приложении одна форма и один учебный [план опроса](configs/protocol-questionnaire.json). Контрольный список вопросов предстоит согласовать с врачом. Врач проверяет черновик и добавляет сведения из осмотра и истории болезни.

## Доработки по замечаниям руководителя

### Мобильное приложение для осмотра в палате

Врач открывает приложение на телефоне, начинает запись перед опросом и останавливает её после разговора. Запись можно прослушать и передать на обработку. После обработки врачу доступны расшифровка, список вопросов из плана, которых приложение не нашло в расшифровке, и черновик протокола для проверки.

Проверка готовности — на телефоне записать вымышленный диалог, остановить запись и получить по ней расшифровку и черновик. Нужно определить, какие действия выполняются на телефоне, а какие на рабочем компьютере или сервере.

### Кнопка «Загрузить шаблон протокола…»

Врач выбирает файл шаблона осмотра. Приложение извлекает названия полей, предлагает вопросы для тех полей, которые заполняются со слов пациента, и показывает предварительный просмотр для подтверждения. Поля, которые врач заполняет по осмотру, анализам или истории болезни, остаются в форме. После подтверждения новый шаблон используется для сопоставления реплик, списка пропущенных вопросов и формирования черновика.

Проверка готовности — загрузить два шаблона с разными полями, увидеть разные формы и списки вопросов, сформировать по каждому черновик без изменения исходного кода. Формат файла для первого запуска следует выбрать по образцу пустого шаблона заказчика. Текущий JSON-сеанс хранит результат отдельного осмотра, а кнопка предназначена для загрузки самой формы.

## Результаты проверок

- В актуальной настольной версии 20 из 20 быстрых автотестов прошли локально. Они проверяют логику обработки, редактирование, сохранение и восстановление, сборку черновика и инструменты сравнения. Тесты с подставленными ответами не оценивают точность моделей.
- В эксперименте по выбору распознавателя сравнили восемь CPU-конфигураций. На шести учебных записях GigaAM v3 CTC показала WER 4,79% и медиану обработки 0,537 с. [План эксперимента](https://github.com/YuraVeseliy/medical-audio-mvp/blob/asr-only-comparison/docs/asr-plan.md) · [Итоговый отчёт](https://github.com/YuraVeseliy/medical-audio-mvp/blob/asr-only-comparison/docs/asr-final-report.md).
- В отдельном сравнении приложений на шести одинаковых учебных записях WER составил 4,79% у MVP, 7,45% у Buzz и 9,04% у Vibe. Все три приложения обработали и сохранили 6 из 6 записей. Время измеряли по записи экрана. Этот замер относится к распознаванию речи.
- В нагрузочном прогоне Locust прошло 25 из 25 измеряемых операций. Проверяли декодирование, распознавание, сохранение JSON и TXT и проверку сохранённых файлов. Самая долгая операция заняла 342,77 с для записи длительностью 120 минут. Формирование черновика моделью Qwen в нагрузочный прогон не входило.

Учебные результаты относятся к указанным сценариям и конфигурациям. Пользовательские записи, заполненные медицинские документы, локальные веса моделей и окружение хранятся вне публичного репозитория.
